# 임시 데이터 시나리오 (MSW)

> 원본: claude.ai 문서 "프론트 디자인" 탭의 "임시 데이터 시나리오" 표. 아래 구체 값(좌표, 계정 비밀번호, 설정값, 시각 오프셋)은 구현을 위해 정한 **임시값**이며 팀 결정이 아니다.

목적: 백엔드 없이 판단 → 재검색 → 번복 → 재확인 필요 → 현재 위치 → 실시간 알림까지 한 번에 테스트하고 시연한다. 응답 모양은 백엔드 `openapi.json`과 `docs/backend-api-final-requests.md`(R1~R7)를 따른다.

- 카메라 12대 C1~C12(source=FIXED)는 캠퍼스 실제 건물 앞(카카오 장소 검색 좌표). 방향·화각(60~110°)은 임시값.
  - C1 대학본부, C2 도서관, C3 학생회관, C4 자연과학대학, C5 체육관, C6 공과대학, C7 사회과학대학, C8 대외협력관, C9 고시생활관, C10 인문대학, C11 창업보육센터, C12 한울관(영상 없음)

## 메인 사건(2026-031) 흐름

실제 동선: C1 → C2 → C3 → C4 → C6.

**초기 상태** (시안과 같음)

- 기준 사진 1장(ready=true). 유사도 기준 0.60.
- C1·C2·C3 확정. 결정 기록에 YES 3건(C1·C2는 user1, C3는 user2).
- 결정 기록에 제외 1건도 넣는다: 예전 단계의 다른 사람 후보 NO(user1). 번복 테스트용.
- 후보 대기열(PENDING):

| 후보 | 장면 | 유사도 | 진짜 여부 | 근거(reasons) | 플래그 |
| --- | --- | --- | --- | --- | --- |
| A | C4 (R−31) | 0.71 | 진짜 | ROUTE_OK "이동 시간 7분 맞음", ROUTE_OK "방향 동→북 맞음", OVERLAP "사람 겹침" | |
| B | C6 (R−26) | 0.66 | 진짜(다음 구간) | ROUTE_OK "경로 일관" | |
| C | C7 (R−35) | 0.63 | 가짜 | TIME_SHORT "이동 시간 부족" | |
| D | C5 (R−30) | 0.62 | 가짜(옷 비슷한 다른 사람) | ROUTE_OK "경로 일관" | |
| E | C11 (R−20) | 0.86 | 가짜 | OUT_OF_FILTER "도보 범위 밖" | out_of_filter=true |
| F·G·H | 아무 카메라 | 0.41 · 0.48 · 0.55 | 가짜 | LOW_QUALITY | below_threshold=true |

- `GET /route`의 `pending`은 후보 A.

**A(C4)에 YES** → 작업(CANDIDATE_SEARCH)이 PROGRESS를 2~3번 거쳐 완료 → 대기열 재구성:

- B(C6) 유사도 0.74로 맨 위, 근거 "이동 시간 5분 맞음".
- 새 가짜 후보 I: C8 (R−24) 0.64, "옷 비슷함".
- C·D·E는 시간상 이전이므로 대기열에서 빠진다(상태는 PENDING 그대로 두되 조회 대상에서 제외해도 됨).

**B(C6)에 YES** → 작업 완료 후 대기열이 빈다. 빈 화면 안내: "더 이상 후보가 없어요. 현재 위치 수색으로 넘어가세요" + [현재 위치 수색].

**번복 규칙** (API 명세와 같음)

- YES 번복: 대상 후보는 PENDING, 그 뒤 확정 장면은 NEEDS_RECHECK. 직전 확정 장면 기준으로 대기열을 그 단계 상태로 되돌린다.
- NO·HOLD 번복: 대상 후보는 PENDING으로 대기열 복귀.
- HOLD: 대기열 맨 뒤로.

**현재 위치** (`search-area`)

- 기준은 마지막 확정 장면(초기: C3, 진행 후: C6).
- levels 3개: 기준 카메라에서 길을 따라 퍼진 다각형(동심원 금지). LOW 영역이 도림제(저수지) 위험 지역과 겹쳐 `danger_overlaps`에 1건.
- priority_zones 3개(예: "가까운 건물 사이 통로", "학생회관 앞 광장", "도림제(저수지) 둘레길 입구").

**실시간 감시**

- 메인 사건에서 감시를 ON으로 바꾸면 60초 뒤 C10 출현 알림 1개(유사도 0.84, NEW).
- YES 응답 → 확정 기록 생성, 동선에 C10 추가. NO → DISMISSED.

## 관리자 데이터

- 녹화 영상 15개: 12개 DONE, `C3_1019_0900.mp4` PROCESSING 62%(조회할 때마다 조금씩 오르다 DONE), `C4_1019_0900.mp4` WAITING, `C2_1019_0900.mp4` FAILED(error_message "프레임 디코딩 실패", 재처리하면 PROCESSING부터 다시).

- 삭제 예정 목록: 사건 3 관련 1건(종료 후 30일 뒤 날짜).

## 응답 조건과 개발 패널

- 모든 응답에 300~800ms 지연. 작업은 약 1초마다 progress 0 → 40 → 80 → 100.
- 가짜 서버 상태는 localStorage에 저장. 새로고침해도 유지.
- 개발 모드에서만 화면 구석에 작은 개발 패널:
  - 데이터 초기화(시각 R을 지금으로 다시 잡고 처음 상태로)
  - 지연 끄기
  - 다음 요청 강제 에러: 401 · 403 · 409 · 500
  - 계정 빠른 전환(admin / user1 / user2)

## 미디어

- 썸네일: 상의 색으로 구분한 사람 모양 그림(SVG 또는 PNG). 진짜 대상은 빨강, 함정은 짙은 빨강·주황·분홍 등 비슷한 색.
- 하이라이트·원본 영상: `public/mock/clips/`에 팀원이 직접 찍은 짧은 mp4를 둔다. 파일이 없으면 재생기 자리에 썸네일과 "영상 없음(가짜 데이터)" 안내를 띄운다.
- 실제 CCTV 영상이나 인터넷에서 받은 사람 사진은 쓰지 않는다.
