# 임시 데이터 시나리오 (MSW)

> 원본: claude.ai 문서 "프론트 디자인" 탭의 "임시 데이터 시나리오" 표. 아래 구체 값(좌표, 계정 비밀번호, 설정값, 시각 오프셋)은 구현을 위해 정한 **임시값**이며 팀 결정이 아니다.

목적: 백엔드 없이 판단 → 재검색 → 번복 → 재확인 필요 → 현재 위치 → 실시간 알림까지 한 번에 테스트하고 시연한다. 응답 모양은 `docs` 브랜치의 `docs/api/openapi.json`과 `docs/api/frontend-api-requests.md`(R1~R7)를 따른다. 아직 openapi.json에 없는 R1~R7 필드도 요청한 모양대로 미리 응답한다.

## 시각 기준

시연 시점과 상관없이 "경과 시간"이 자연스럽게 보이도록, 모든 시각은 **데이터를 초기화한 시각 R** 기준 상대값으로 만든다. 괄호 안은 시안(10/19)에 대응하는 시각이다. 응답 시각은 UTC(`Z`) RFC3339이고 화면은 한국 시간으로 보여 준다.

## ID

- 백엔드 정수 ID(user_id, case_id, node_id, camera_id, zone_id, edge_id, video_id)는 가짜 DB에 숫자 문자열로 둔다. 예: 사용자 1·2·3, 사건 31·32·29, 카메라 C3 → 3, 사건 영상 카메라 P1 → 101.
- 10진수 문자열 ID(tracklet_id, decision_id, alert_id 등)는 내부 id에 `pubId`로 1001부터 차례로 매긴다. 검색 search_id·task_id는 UUID.

| admin | test1234 | 관리자 | admin | 모든 사건 열람 |
| user1 | test1234 | 김수색 | user | 사건 31(주 담당자), 32(주 담당자) |
| user2 | test1234 | 이수색 | user | 사건 31(공동 담당), 29. `must_change_password=true`로 시작 |

- user1은 사건 29를, user2는 사건 32를 볼 수 없다(**404** "사건을 찾을 수 없거나 접근 권한이 없습니다" 테스트).
- 시드 계정의 비밀번호는 8자지만, 새로 바꾸는 비밀번호는 10~128자다(openapi.json 제안). user2 첫 로그인 때 10자 이상으로 바꾼다.
- 인증은 세션 쿠키 `refind_session` + CSRF 토큰. 가짜 서버는 브라우저 안에서 돌기 때문에 같은 이름의 쿠키를 직접 쓴다(HttpOnly 흉내). 세션은 60분 동안 쓰지 않으면 끝난다.

## 지도

- 중심: 국립목포대학교 도림캠퍼스(무안군 청계면, 약 34.9103, 126.4378). 2026-11-16 사용자 요청으로 바꿈.
- 카메라 12대 C1~C12는 캠퍼스 실제 건물 앞(카카오 장소 검색 좌표). 서버 이름은 "C3 학생회관 앞"처럼 코드로 시작하고, 화면이 앞부분을 코드로 읽는다. 방향·화각(60~110°)은 임시값.
  - C1 대학본부, C2 도서관, C3 학생회관, C4 자연과학대학, C5 체육관, C6 공과대학, C7 사회과학대학, C8 대외협력관, C9 고시생활관, C10 인문대학, C11 창업보육센터, C12 한울관(영상 없음)
- 위험 지역 1곳: 캠퍼스 남쪽 저수지 둘레 다각형, 이름 "도림제(저수지)", kind=water, severity=high.
- 도보 구간(walk-graph): 이웃한 카메라끼리 20개. `C1→C5`는 suspected_detour=true, API 820m·11분, 직접 수정 300m·4분(source=manual). `C2→C4`는 API 1.2km·16분.
- 사건 31에는 사건 영상 카메라 1대(P1 "MNU라운지 앞(편의점 블랙박스)", 네모 마커)를 둔다. 서버 카메라 응답에는 사건 전용 여부가 없어서, 화면은 `case_id`를 넣은 목록과 전역 목록을 비교해 구분한다.

## 메인 사건(31) 흐름

실제 동선: C1 → C2 → C3 → C4 → C6.

**초기 상태** (시안과 같음)

- 기준 사진 1장(ready). 유사도 기준 0.60.
- C1·C2·C3 확정. 결정 기록에 예 3건(C1·C2는 user1, C3는 user2)과 아니오 1건(예전 단계의 다른 사람, user1, 번복 테스트용).
- **C3 기준으로 이미 끝난 검색 하나**(search_id 고정)를 넣어 둔다. 새로고침하면 사건의 `latest_search`로 이 검색이 복원된다.
- 이 검색의 후보:

| 후보 | 장면 | 유사도 | 진짜 여부 | 근거(서버 reason_codes / summary) |
| --- | --- | --- | --- | --- |
| A | C4 (R−31) | 0.71 | 진짜 | TIME_FEASIBLE, MANUAL_REVIEW_REQUIRED · "이동 시간 7분 맞음 · 방향 동→북 맞음 · 사람 겹침" |
| B | C6 (R−26) | 0.66 | 진짜(다음 구간) | TIME_FEASIBLE · "경로 일관" |
| C | C7 (R−35) | 0.63 | 가짜 | MANUAL_REVIEW_REQUIRED · "이동 시간 부족" |
| D | C5 (R−30) | 0.62 | 가짜(옷 비슷한 다른 사람) | TIME_FEASIBLE · "경로 일관" |
| E | C11 (R−20) | 0.86 | 가짜 | time_feasible=false, TIME_REVIEW_REQUIRED(범위 밖이지만 0.85 이상이라 포함, R5) |
| F·G·H | 아무 카메라 | 0.41 · 0.48 · 0.55 | 가짜 | 유사도 기준 미만이라 **응답에 없음** |

**A(C4)에 예** → 사건 버전 +1, 그 전 검색은 낡음(stale) → 화면이 C4 확정을 기준(`anchor_decision_id`)으로 새 검색을 바로 요청 → 작업이 0 → 40 → 80 → 100(약 7.5초) → 새 검색의 후보:

- B(C6) 유사도 0.74로 맨 위, "이동 시간 5분 맞음".
- 새 가짜 후보 I: C8 (R−24) 0.64, "옷 비슷함".
- 개발 패널 "다시 검색하면 새 후보 1~2개"가 켜져 있으면 가짜 새 후보도 1~2개 생긴다.

**B(C6)에 예** → 새 검색이 끝나면 후보가 없다. 빈 화면 안내: "더 이상 후보가 없어요. 현재 위치 수색으로 넘어가세요" + [현재 위치 수색].

**검색이 낡는(stale) 경우** (가짜 서버 해석, 백엔드 확인 필요)

- 기준 대상(사진·트랙렛)이나 유사도 기준이 바뀔 때
- "예" 판단, 출현 알림 "맞아요"
- 예·아니오 판단의 번복
- 아니오·보류 판단과 **보류의 번복**은 검색을 낡게 하지 않는다(요청서 R3)

**판단·번복 규칙**

- 판단은 search_id·tracklet_id·사건 버전을 함께 보낸다. 사건 버전이 다르면 409 `VERSION_CONFLICT`, 다른 담당자가 먼저 판단했으면 409 `ALREADY_DECIDED`.
- 예 번복: 대상 후보는 대기로, 그 뒤 확정 장면은 재확인 필요(needs_reconfirmation). 검색은 낡는다.
- 아니오 번복: 다시 검색하면 그 후보가 다시 나온다.
- 보류: 대기열 맨 뒤. 보류한 후보를 판단하면 보류를 번복(사유 없음)한 뒤 같은 검색에서 새로 저장한다.
- 확정한 장면이 있으면 기준 대상(사진)을 바꿀 수 없다(409 `CONFIRMED_HISTORY_EXISTS`).

**현재 위치** (`GET search-area`, 조회할 때 계산)

- 기준은 마지막 확정 장면(초기 C3, 진행 후 C6·C10). 확정이 없으면 사건의 마지막 목격 위치·시각 기준이고 경고 1건.
- levels 3개(1 높음·2 중간·3 낮음): 기준 위치에서 길을 따라 퍼진 십자 모양(동심원 금지). 낮음 영역이 도림제와 겹쳐 `hazard_overlaps` 1건.
- priority_areas 3개("이탈 방향(남쪽)으로 가장 가까운 통로", "학생회관 앞 광장", "도림제(저수지) 둘레길 입구").

**실시간 감시**

- 감시를 켜면 5초 동안 starting, 그 뒤 watching(분석된 영상이 있는 카메라 11대).
- 메인 사건에서 감시를 켜면 60초 뒤 C10 출현 알림 1개(유사도 0.84, 높음 기준 0.80 이상이라 level=high, pending).
- "맞아요" → 출처가 출현 알림(source_type=alert)인 확정 판단, 동선에 C10 추가. "아니요" → rejected 판단. 알림 판단을 번복하면 알림이 다시 pending.
- 사이드바 배지는 `/alerts/pending-count`(R2): 진행 중 사건의 pending 알림 수.

## 관리자 데이터

- 녹화 영상 15개(전역): 12개 done, C3 영상 running(조회할 때마다 조금씩 올라 done), C4 영상 queued, C2 영상 failed("프레임 디코딩 실패", 재처리하면 queued부터 다시). 파일 이름에 "fail"이 들어간 영상을 올리면 분석이 실패한다(실패 화면 확인용).
- 전체 현황 `/videos/stats`(R7)는 전역 영상만 센다.
- 이용 기록 20건 정도: login, search, decision, revert, video_view, account_change 섞어서. 서버 기록 모양이라 설명 문장 없이 대상(자원)만 있다.
- 삭제 예정 목록: 종료 사건 29(종료 후 30일), 녹화 영상들(녹화 후 90일). 확정 동선에 쓰인 영상은 "보호"로 표시. 자동 삭제는 하지 않는다.

## 응답 조건과 개발 패널

- 모든 응답에 300~800ms 지연. 작업은 단계적으로 progress가 오른다.
- 가짜 서버 상태는 localStorage에 저장. 새로고침해도 유지. 가짜 DB 구조를 바꾸면 `DB_VERSION`을 올려 처음 상태로 다시 만든다.
- 개발 모드에서만 화면 왼쪽 아래에 작은 개발 패널:
  - 계정 빠른 전환(admin / user1 / user2)
  - 다음 요청 강제 에러: 401(SESSION_EXPIRED) · 403 · 409(VERSION_CONFLICT) · 500
  - 응답 지연 끄기
  - 다시 검색하면 새 가짜 후보 1~2개
  - 데이터 초기화(시각 R을 지금으로 다시 잡고 처음 상태로)

## 미디어

- 썸네일: 상의 색으로 구분한 사람 모양 그림(SVG). 진짜 대상은 빨강, 함정은 짙은 빨강·주황·분홍 등 비슷한 색. `/api/tracklets/{id}/thumbnail`, `/api/cases/{id}/alerts/{id}/snapshot`이 이 파일을 돌려준다.
- 원본 영상: `public/mock/clips/`에 팀원이 직접 찍은 짧은 mp4를 두면 `/api/videos/{id}/stream`이 돌려준다. 파일이 없으면 재생기 자리에 "영상 없음(가짜 데이터)" 안내를 띄운다. 하이라이트는 생성 방식이 미정(D01)이라 늘 not_available이다.
- 실제 CCTV 영상이나 인터넷에서 받은 사람 사진은 쓰지 않는다.
