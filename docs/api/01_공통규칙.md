## 이 문서에서 다루는 것

- 모든 API가 따르는 약속: 주소, 데이터 형식(시각·좌표·방향·거리·속도 단위), 응답 모양
- 목록 응답은 `items/total/page/per_page` 형식, 에러는 모두 `{"error": {code, message, details}}` 하나의 형식
- 상태 코드 표와 에러 코드 10개 목록
- 오래 걸리는 작업은 `202` + `task_id`를 받고 `/api/tasks/{task_id}`를 2~3초마다 조회하는 방식
- 업로드 제한: 영상 mp4/avi/mov 2048MB, 사진 jpg/png 10MB
- 참고: 원본에 1.2절 번호가 없음(1.1 다음이 1.3)

## 1. 공통 규칙

### 1.1 기본 주소

| 구분 | 주소 | 설정 담당 |
|---|---|---|
| 외부 API | `/api` (상대 경로) | 프론트는 경로만 사용 |
| 내부 API | 환경변수 `GPU_SERVER_URL` | 백엔드 |
| 자동 문서 | FastAPI `/docs` (Swagger), `/openapi.json` | 백엔드 |

#### 서버 구성과 주소 관리

- 일반 도커 서버: nginx가 React 빌드 파일을 제공하고 `/api` 요청을 FastAPI로 넘긴다.
- GPU 서버: 백엔드만 호출한다. 외부 접근은 막는다.
- 프론트 코드에는 IP 주소를 넣지 않는다. 개발 중에는 Vite 프록시를 쓰고, 주소는 각자의 `.env.local`의 `API_TARGET`에 둔다.
- 실제 주소는 백엔드가 설정하고 공유한다. `.env`, `.env.local`은 git에 올리지 않는다.

### 1.3 데이터 형식

| 항목 | 형식 | 예시 |
|---|---|---|
| 시각 | ISO 8601, 한국 시간대 표기 | `"2026-11-08T14:30:00+09:00"` |
| 영상 내 위치 | 초 단위 실수 | `"video_offset_sec": 125.4` |
| 좌표 | WGS84 위도·경도 | `{"lat": 37.5665, "lng": 126.9780}` |
| 폴리곤 | 좌표 배열, 첫 점과 끝 점을 같게 하지 않음(서버가 닫음) | `[{"lat":..,"lng":..}, ...]` |
| 방향 | 북쪽 0도 기준 시계 방향, 0 이상 360 미만 | `"direction_deg": 90` |
| 거리 | 미터 | `"distance_m": 42.5` |
| 속도 | 미터/초 | `"speed_mps": 1.1` |

### 1.4 성공 응답

- 단건: 리소스 객체를 그대로 반환한다.
- 목록: 아래 형식으로 반환한다.

```json
{
  "items": [ ... ],
  "total": 42,
  "page": 1,
  "per_page": 20
}
```

- 목록 공통 쿼리: `page`(기본 1), `per_page`(기본 20, 최대 100)

### 1.5 에러 응답

모든 에러는 같은 형식으로 반환한다. FastAPI 기본 422 형식(`{"detail": [...]}`)도 예외 처리기에서 이 형식으로 바꾼다.

```json
{
  "error": {
    "code": "validation_error",
    "message": "입력값이 올바르지 않습니다.",
    "details": [
      { "field": "location.lat", "message": "-90 이상 90 이하여야 합니다.", "code": "out_of_range" }
    ]
  }
}
```

- 500 응답에는 내부 정보(스택, SQL 문)를 넣지 않는다. 상세 내용은 서버 로그에만 남긴다.

### 1.6 상태 코드

| 코드 | 사용하는 경우 |
|---|---|
| 200 OK | 조회, 수정 성공 |
| 201 Created | 생성 성공. `Location` 헤더에 새 리소스 주소 |
| 202 Accepted | 오래 걸리는 작업을 접수함. 완료가 아님 |
| 204 No Content | 삭제 성공 |
| 206 Partial Content | 영상 Range 요청 응답 |
| 400 Bad Request | 파일 형식 오류, 잘못된 요청 본문 |
| 404 Not Found | 리소스 없음 |
| 409 Conflict | 상태 충돌 (예: 연결된 영상이 있는 카메라 삭제, 분석이 끝나지 않은 사건 검색) |
| 413 Payload Too Large | 업로드 크기 초과 |
| 416 Range Not Satisfiable | 영상 Range 범위 오류 |
| 422 Unprocessable Entity | 입력값 검증 실패 |
| 500 Internal Server Error | 예상하지 못한 서버 오류 |
| 502 Bad Gateway | GPU 서버 응답 실패 |

### 1.7 에러 코드 목록

| code | HTTP | 의미 |
|---|---|---|
| `validation_error` | 422 | 입력값 검증 실패. `details`에 필드별 사유 |
| `invalid_file` | 400 | 파일 형식이 허용되지 않거나 손상됨 |
| `file_too_large` | 413 | 업로드 크기 초과 |
| `not_found` | 404 | 리소스 없음 |
| `resource_in_use` | 409 | 다른 데이터가 참조하고 있어 삭제할 수 없음 |
| `invalid_state` | 409 | 현재 상태에서 할 수 없는 요청 |
| `not_ready` | 409 | 분석·특징 추출이 끝나지 않음 |
| `range_not_satisfiable` | 416 | 영상 Range 범위 오류 |
| `gpu_server_error` | 502 | GPU 서버 요청 실패 |
| `internal_error` | 500 | 서버 내부 오류 |

### 1.8 오래 걸리는 작업 (비동기 작업)

영상 분석, 사진 특징 추출, 후보 검색, 판정 후 재계산은 같은 방식으로 처리한다.

1. 클라이언트가 요청하면 서버는 `202`와 `task_id`를 바로 반환한다.
2. 클라이언트는 2~3초 간격으로 `GET /api/tasks/{task_id}`를 호출한다.
3. `status`가 `SUCCESS`나 `FAILURE`가 되면 조회를 멈추고, 결과 리소스를 조회한다.

```json
HTTP/1.1 202 Accepted
{
  "task_id": "6f1c2a9e-3b7d-4c1a-9f0e-2d8b7a1c5e44",
  "status_url": "/api/tasks/6f1c2a9e-3b7d-4c1a-9f0e-2d8b7a1c5e44"
}
```

- Redis의 작업 상태는 임시 데이터다. 새로고침 후에는 리소스 자체의 `status`(영상, 사건, 검색)를 기준으로 상태를 복구한다.

### 1.9 업로드 제한

| 대상 | 허용 형식 | 최대 크기 (설정값, 기본 제안) |
|---|---|---|
| 영상 | mp4, avi, mov | `MAX_VIDEO_SIZE_MB` = 2048 |
| 사진 | jpg, jpeg, png | `MAX_PHOTO_SIZE_MB` = 10 |

- 확장자만 보지 않고 ffprobe(영상), 이미지 디코딩(사진)으로 실제 파일을 검증한다.
