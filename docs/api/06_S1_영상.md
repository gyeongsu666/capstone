## 이 문서에서 다루는 것

- CCTV 영상을 올리고 분석 상태를 관리하는 API 7개
- 업로드하면 `202`와 `task_id`를 받고, 상태는 `uploaded` → `converting` → `analyzing` → `ready`(또는 `failed`)로 바뀐다
- `ready` 상태 영상만 검색 대상이 된다
- 실제 시각 = 녹화 시작 시각 + 영상 내 위치 + 보정 오프셋. 보정은 PATCH로 한다
- 실패한 영상은 `retry`로 다시 분석하고, 재생은 `stream`(Range 요청 지원)으로 한다

## 6. S1 영상 준비: 영상

### 영상 객체

```json
{
  "id": 12,
  "camera_id": 3,
  "original_filename": "cam3_1108.mp4",
  "status": "analyzing",
  "recorded_start_at": "2026-11-08T13:00:00+09:00",
  "time_offset_sec": 0.0,
  "duration_sec": 600.0,
  "width": 1920,
  "height": 1080,
  "fps": 30.0,
  "tracklet_count": null,
  "task_id": "6f1c2a9e-3b7d-4c1a-9f0e-2d8b7a1c5e44",
  "error": null,
  "stream_url": "/api/videos/12/stream",
  "created_at": "2026-11-08T13:20:00+09:00"
}
```

| `status` | 의미 | 검색 대상 |
|---|---|---|
| `uploaded` | 업로드 완료, 작업 대기 | X |
| `converting` | 재생용 mp4 변환 중 | X |
| `analyzing` | 검출·추적·특징 추출 중 | X |
| `ready` | 분석 완료 | O |
| `failed` | 실패. `error`에 사유 | X |

- 실제 시각 = `recorded_start_at` + 영상 내 위치 + `time_offset_sec`

### 6.1 `POST /api/videos` 영상 업로드

- 요청: `multipart/form-data`

| 필드 | 필수 | 설명 |
|---|---|---|
| `file` | O | 영상 파일 |
| `camera_id` | O | 촬영 카메라 |
| `recorded_start_at` | O | 녹화 시작 시각 |
| `time_offset_sec` | X | 보정 오프셋, 기본 0 |

```json
202 Accepted
Location: /api/videos/12
{
  "video_id": 12,
  "task_id": "6f1c2a9e-3b7d-4c1a-9f0e-2d8b7a1c5e44",
  "status_url": "/api/tasks/6f1c2a9e-3b7d-4c1a-9f0e-2d8b7a1c5e44"
}
```

- 에러: `400 invalid_file`, `413 file_too_large`, `404 not_found` (카메라 없음), `422 validation_error`

### 6.2 `GET /api/videos` 영상 목록

- 쿼리: `camera_id`, `status`, `page`, `per_page`
- 응답: `200`, 영상 객체 목록

### 6.3 `GET /api/videos/{video_id}` 영상 정보

- 응답: `200`, 영상 객체
- 에러: `404 not_found`

### 6.4 `PATCH /api/videos/{video_id}` 시각 보정

- 요청: `{"recorded_start_at": "...", "time_offset_sec": -2.5}` (바꿀 필드만)
- 응답: `200`, 영상 객체
- 이미 저장된 트랙렛의 실제 시각도 새 값으로 계산된다.
- 에러: `404 not_found`, `422 validation_error`

### 6.5 `DELETE /api/videos/{video_id}` 영상 삭제

- 원본·재생용 파일, 썸네일, 트랙렛, 특징 벡터를 함께 삭제한다.
- 응답: `204`
- 에러: `404 not_found`, `409 invalid_state` (분석 중에는 삭제 불가), `409 resource_in_use` (확정 판정에 쓰인 트랙렛이 있음)

### 6.6 `POST /api/videos/{video_id}/retry` 분석 재시도

- `failed` 상태에서만 가능하다. 이전 실행이 남긴 트랙렛·벡터를 지운 뒤 다시 실행해 중복을 막는다.
- 응답: `202`, `{"video_id", "task_id", "status_url"}`
- 에러: `404 not_found`, `409 invalid_state` (`failed`가 아님)

### 6.7 `GET /api/videos/{video_id}/stream` 재생용 영상

- 요청 헤더: `Range: bytes=0-1048575` (선택)
- 응답: Range 없으면 `200`, 있으면 `206`과 `Content-Range` 헤더. `Content-Type: video/mp4`
- HTML5 video에서 `#t={video_offset_sec}`로 원하는 위치부터 재생한다.
- 에러: `404 not_found`, `409 not_ready` (변환 전), `416 range_not_satisfiable`
